# Section Guides

Use this reference when drafting, revising, or diagnosing specific sections of a Chinese academic paper.

## 摘要

摘要不是把全文简单缩短，而是要回答四个问题：

- 研究什么问题。
- 现有方法有什么不足。
- 提出了什么方法。
- 方法效果怎么样，意义是什么。

常用结构为“背景-问题-方法-结果-结论”：

1. 用 1 句话交代研究对象及研究意义，说明问题为什么值得研究。
2. 用 1 句话指出当前方法的核心不足，明确本文切入点。
3. 用 2-4 句话概述所提出的方法，说明框架、主要实现思路，以及要解决的关键问题。
4. 用 1 句话给出实验结果，最好包含数据集名称、核心评价指标，以及与对比方法相比的性能提升。
5. 用 1 句话总结研究结论与实际意义，说明实验结果表明了什么，以及该方法能为相关任务提供怎样的支持。

注意事项：

- 不要写成引言式长背景。
- 不要只写“本文方法有效”，要给出具体指标或明确保留占位符。
- 不要首次引入正文没有支撑的夸大结论。

## 引言

引言的任务不是介绍知识，而是建立研究必要性，把读者一步一步带到“这个方法确实值得做”的结论上。

引言通常回答四个问题：

- 为什么开展这项研究。
- 别人已经做了哪些大方向研究。
- 现有方法还存在哪些不足。
- 本文针对这些不足提出了什么方法，贡献是什么。

常用结构为“背景-现状-不足-本文工作”：

1. 用 1 段说明研究对象的背景和意义，交代问题为什么重要、为什么值得研究。
2. 用 1 段概述该领域已有的主要研究方法或技术路线，说明目前通常如何解决这一问题。
3. 用 1 段分析现有方法的主要不足，重点指出这些不足对研究目标造成的限制。
4. 用 1 段说明本文提出的方法或框架，并概括主要贡献，使读者明确创新点和研究价值。

注意事项：

- 研究现状只需概括大方向，细节留给相关工作。
- 不足要和本文方法一一对应。
- 贡献应具体，避免空泛的“具有重要意义”。

## 相关工作

相关工作的任务不是罗列文献，而是说明“别人已经做了什么、做到什么程度、还留下了什么问题”。它比引言更细致，并为本文方法提供依据。

相关工作通常回答四个问题：

- 该领域已有研究主要沿哪些技术路线展开。
- 不同技术路线分别解决了什么问题。
- 现有方法在特征表达、泛化能力、复杂度、可解释性或应用方面仍有什么不足。
- 本文方法主要针对哪个尚未充分解决的问题。

常用结构为“研究任务-方法分类-不足总结-本文定位”：

1. 简要说明研究方向的发展现状，指出已有研究主要围绕哪些问题展开。
2. 按技术路线或研究重点分类介绍已有方法，例如传统特征提取、机器学习、深度学习、注意力机制、图模型、多模态方法等。
3. 每一类方法先概括基本思想，再列举代表性研究，最后指出局限性。
4. 综合分析现有研究的共性问题，例如特征表达能力不足、泛化能力有限、跨被试性能不稳定、可解释性不足或计算复杂度较高。
5. 自然引出本文工作，说明本文针对哪些不足提出，以及与已有研究的区别。

注意事项：

- 不要一篇文献一句话堆叠。
- 分类标准要清楚，可以按技术路线、任务阶段、数据类型或研究问题分类。
- 不要把本文贡献写成凭空出现，要从已有不足自然推出。

## 方法

方法部分的任务不是重复介绍模型背景，而是清楚说明“本文是怎么做的”。读者应能理解整体流程、核心模块、实现细节和设计理由。

方法通常回答四个问题：

- 研究任务如何定义，输入和输出分别是什么。
- 本文方法的整体框架是什么。
- 模型由哪些模块组成，各模块功能是什么。
- 关键改进体现在哪里，为什么这样设计。

常用结构为“问题定义-总体框架-核心模块-输出过程-方法小结”：

1. 明确研究任务，说明研究对象、输入数据、输出结果，以及任务属于分类、检测、分割、预测、回归还是优化问题。
2. 介绍总体框架，说明方法由哪些主要部分组成，以及数据在各部分之间如何流动。
3. 按执行顺序或前向传播过程介绍核心模块、关键步骤或算法流程。
4. 重点说明改进部分的设计动机、实现方式和功能作用。
5. 说明方法如何得到最终输出，并总结各模块之间的协同关系以及相较已有方法的主要改进。

注意事项：

- 少讲通用背景，多讲本文具体实现。
- 每个模块都要说明输入、处理过程、输出、作用。
- 创新点要同时写“怎么做”和“为什么这样做”。

## 实验结果

实验结果部分的任务不是展示表格和数字，而是证明“本文方法是否有效”。它需要说明本文方法相比已有方法是否有优势，关键模块是否发挥作用，以及方法在不同条件下是否稳定、有应用价值。

实验结果通常回答六个问题：

- 实验在什么条件下进行。
- 本文方法与已有方法相比表现如何。
- 提出的关键模块是否有效。
- 不同参数或实验条件是否影响性能。
- 模型结果是否具有可解释性。
- 性能与复杂度之间是否平衡。

常用结构为“实验设置-对比实验-消融实验-参数分析-可视化分析-复杂度分析-结果小结”：

1. 介绍数据集、数据划分、评价指标、对比方法、训练参数、硬件环境和实现细节。
2. 将本文方法与传统方法、经典模型和近年代表性方法比较，说明主要指标表现。
3. 通过去除、替换或简化关键模块进行消融实验，验证各改进部分是否有效。
4. 进行参数敏感性、鲁棒性或跨场景分析，考察稳定性。
5. 用混淆矩阵、特征分布图、热力图、注意力图、可视化案例或降维图解释模型结果。
6. 从参数量、计算量、运行时间、推理速度或资源消耗分析复杂度，并总结实验结果。

注意事项：

- 实验设置写条件，不重复方法原理。
- 对比实验要公平，尽量使用相同数据划分、指标和实验条件。
- 消融实验要对应创新点。
- 结果描述不能只说“最好”，要结合指标说明提升幅度和趋势。
- 正文不需要重复表格所有数字，应突出关键差异和结论。
- 若强调轻量化、实时性或应用价值，应补充复杂度分析。

## 讨论

讨论部分的任务不是重复实验结果，而是解释“实验结果说明了什么”。它连接研究问题、已有研究和实际应用，体现分析深度。

讨论通常回答五个问题：

- 最重要的实验发现是什么。
- 这些结果可能由什么原因造成。
- 与已有研究相比有什么一致或不同之处。
- 对相关研究或实际应用有什么价值。
- 还存在哪些局限，未来可以如何改进。

常用结构为“主要发现-原因解释-文献比较-研究意义-局限与展望”：

1. 概括最能支撑研究目标的实验发现。
2. 结合方法设计、数据特点、模型结构或任务需求解释原因。
3. 与已有研究比较，说明一致、改进或不同之处。
4. 说明理论意义、方法意义或应用价值，例如提升性能、增强泛化、降低复杂度，或提供新的解决思路。
5. 客观指出局限性，并提出未来完善方向。

注意事项：

- 讨论必须建立在实验结果上。
- 不要把实验结果重新描述一遍，要解释原因和意义。
- 主动说明不足。
- 避免过度夸大，使用克制表达。
- 与引言提出的问题和不足形成呼应。

## 结论

结论部分不是重复摘要，也不是重新罗列实验结果，而是凝练回答“本文最终得出了什么结论”。

结论通常回答四个问题：

- 研究了什么问题。
- 提出了什么方法或开展了什么工作。
- 得到了什么主要结果。
- 工作有什么意义，未来还可以如何完善。

常用结构为“研究问题-本文工作-主要发现-研究意义-未来方向”：

1. 简要回顾研究问题，说明围绕什么任务或现象展开。
2. 概括提出的方法、模型、框架或分析思路。
3. 总结最重要的实验结果或研究发现，说明它们如何支持结论。
4. 说明理论、方法或实际应用价值。
5. 简要指出未来方向，例如扩大数据规模、优化模型结构、提高泛化能力、增强可解释性或开展真实场景验证。

注意事项：

- 简洁明确，不再展开大量原因分析。
- 与引言呼应。
- 不引入新的实验结果、方法细节或参考文献。
- 避免过度夸大。
- 未来工作要短，不削弱当前工作的完整性。

## 参考文献及附属声明

结论之后通常不再继续展开正文论证，而是按期刊、会议或学校要求补充：

- 参考文献。
- 基金资助。
- 作者贡献。
- 利益冲突。
- 伦理审批。
- 数据可用性。
- 代码可用性。
- 致谢。
- 附录。

这些内容不直接参与正文论证，但体现规范性、透明性和可复现性。必须严格基于真实信息填写，不要代用户编造。
